## 1. The 80/20 evidence

A small-N inventory of foundational properties:

### 1.1 Typography restraint

| Size | Count | Cumulative share |
|---|---|---|
| `text-sm` | 922 | 45% |
| `text-xs` | 590 | 74% |
| `text-[11px]` | 156 | 81% |
| `text-[10px]` | 107 | 86% |
| `text-base` | 66 | 89% |
| `text-lg`/`xl`/`2xl`+ | 268 | 100% |

**~86% of text is `sm` or smaller.** The repo whispers, never
shouts. Large display sizes (`3xl`/`4xl`/`5xl`) total just 31
instances across ~1900 — reserved for hero moments only.

### 1.2 Font weight restraint

5 of 9 Tailwind weights used:

| Weight | Count |
|---|---|
| `font-semibold` | 655 |
| `font-medium` | 515 |
| `font-bold` | 175 |
| `font-normal` | 9 |
| `font-black` | 2 |

**Zero `font-thin` / `font-extralight` / `font-light` / `font-extrabold`.**
The repo restricts itself to the middle-and-upper-middle range. No
delicacy (thin = fragility risk on dense data), no aggression
(extrabold = visual shouting). Bold is rare (175 vs medium 515) —
roughly 1:3 ratio. Even emphasis is restrained.

### 1.3 Color tone preference (warm-over-alarm)

| Family | Approx count |
|---|---|
| `bg-amber-*` (warm/premium tones) | ~140 |
| `bg-red-*` (alarm tones) | ~50 |

**Amber outweighs red roughly 3:1.** The codebase prefers WARM
(premium gold/champagne) over ALARM (error red). When the design
needs to attract attention, it does so through warmth (status
chips, hover halos) before it does so through alarm (only true
errors).

### 1.4 Visual shouting bounded

- 174 `uppercase` instances total
- Almost exclusively reserved for: section eyebrows, badge labels,
  status chips, and category tags
- Body text and headings stay sentence-case

### 1.5 The restraint principles inventory

From this and prior passes, the foundational restraint set:

1. **Size restraint** — 86% sm-or-smaller text
2. **Weight restraint** — 5 of 9 weights, no extremes
3. **Color tone preference** — warm 3:1 over alarm
4. **Uppercase containment** — reserved for marker/label roles
5. **Density restraint** — 85% of gaps in `gap-1`-`gap-3` (Pass 21)
6. **Motion restraint** — `duration-200` dominant (90 of ~200 uses), nothing slower than 1000ms (Pass 21)
7. **Touch-target floor** — 198× `min-h-[44px]` (Pass 21)

Seven primitives. None require infrastructure. None require dialect
families. None require z-tier pyramids. **All transplant trivially.**

## 2. The portability classification

### 2.1 HUMAN-PORTABLE (the 20% that produces 80% of the calmness)

These transplant directly to any organism, including Stacey:

- The **Seven Restraint Primitives** (§1.5)
- The **warm-over-alarm color preference** (cultural signal, not infrastructure)
- The **per-surface design choice** between `truncate` and `flex-wrap` (the CHOICE, not the helper)
- The **physics-of-arrival principle** — slow-from-bottom, quick-from-top, calm-from-edge, snappy-zoom (the principle, not the constants)
- The **anti-shouting discipline** — uppercase only as marker, bold only as emphasis, no display sizes outside hero moments
- The **CSS-first reduced-motion contract** (the architectural lock, not the specific guards)

### 2.2 ORGANISM-SPECIFIC (the 80% that produces the remaining 20% — premium polish, BD-only)

These should NOT transplant. Stacey requires its own organism-specific elaborations:

- **Exact blur tier values** (sm/md/xl/2xl/3xl breakdown is BD's calibration)
- **Exact duration constants** (200/300/400/500/700/1000 is BD's pacing)
- **Z-tier topology** (38+ values across 8 operating layers is BD's attention hierarchy for a map-first organism)
- **The `map-liquid-*` dialect** (BD-specific liquid metaphor for spatial UI)
- **The `bd-dashboard-*` 12-variant dialect** (BD's dashboard region voice)
- **Navigation choreography** (turn-by-turn maneuver staging is BD's mission-critical layer)
- **The distributed continuity timing network** (Pass 305's builder-side discovery — BD's compound)

### 2.3 The split test

A useful sanity check: imagine writing Stacey from scratch using
ONLY the §2.1 portable principles. Would the result feel **calm**?

Almost certainly yes. The seven restraint primitives alone produce:
- Whispered typography
- Restrained emphasis
- Warm color cast
- Comfortable density
- Soft motion
- A11y-respectful touch targets
- Reduced-motion respect

This is most of "premium calmness" already. The dialect topology,
blur tiers, and choreography networks ADD polish — they don't
CREATE the foundational feel.

**Hypothesis confirmed:** restraint consistency, not choreography
complexity, is the dominant calmness mechanism.

## 3. The continuity-without-choreography test (Priority C)

If choreography were essential to the felt calmness, removing it
would collapse the experience. But the seven restraint primitives
don't depend on choreography:

| Restraint primitive | Requires choreography? |
|---|---|
| Size restraint | No — pure CSS |
| Weight restraint | No — pure CSS |
| Color tone preference | No — pure values |
| Uppercase containment | No — pure CSS |
| Density restraint | No — pure CSS |
| Motion restraint | Partial — `duration-200` is a value, not a system |
| Touch-target floor | No — pure CSS |

**Six of seven primitives require zero choreography infrastructure.**
The seventh (motion restraint) is itself a restraint principle, not
a choreography system.

This means a minimal organism — one with the seven primitives but
no dialect topology, no map-liquid family, no z-tier pyramid, no
provider stack — would still feel calm. It would not feel
*premium* the way BidOnDent does, but it would feel *calm*.

**Stacey can begin from this minimal state and grow its own
elaborations.** The temptation to port BD's elaborations whole-cloth
is the trap the brief warned about.
